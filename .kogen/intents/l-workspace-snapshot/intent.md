# Open small repositories with a workspace snapshot

Slug: l-workspace-snapshot
Model: not applicable — the snapshot is computed once from the repository when a Session's conversation is still empty and becomes an ordinary user message of that conversation; resume, later rounds, transcripts and condensation keep their existing rules, so no new state or transition exists
Acceptance:
- .kogen/intents/l-workspace-snapshot/acceptance.feature
- features/steps/l_workspace_snapshot.js

Fix L-WORKSPACE-SNAPSHOT in kogen-loop (Studio kogen-loop issue 684e0568-ae9d-480b-9853-4b171e5d3e7d, v2). In a new Session the model's first two requests on a small repository are always orientation: list the files, then read nearly all of them, and only then edit. After this change, the opening round of a `loop.Session` on a small repository gives the model that workspace up front. The opening input stays the unchanged task text `{"role":"user","content":<task text>}`, and exactly one more user message `{"role":"user","content":<snapshot>}` follows it. The snapshot holds a fixed header, the exact `list_files` output and the exact `read_file` output of every listed file of at most 4096 bytes. Larger, binary, invalid-UTF-8, refused and non-regular files appear in the listing only.

The snapshot is added only when all of these hold, and otherwise the opening is byte-identical to today:
- The Session's conversation is empty. That is the first `Round` of a `NewSession`, or a later `Round` on a Session whose earlier rounds all failed, since a failed round leaves the conversation empty. `ResumeSession` rounds and every later round never add one. Feedback is appended exactly as today.
- Both `list_files` and `read_file` are among the Session's enabled tools. The default tool set has both.
- `list_files` with no arguments succeeds and lists at least one path. A root that is not a Git repository (the `error:` text) or an empty repository (`(no files)`) gets no snapshot.
- The listing has at most 64 paths, and the shown files total at most 32768 bytes.

The message is computed before the round's first request. It then becomes part of the conversation: later requests of the round carry it once, in the same place. It is written to `session.json` and survives resume. Condensation keeps it exact, like every user message. `loop.Run`, the engine Kogen's native builder calls with its own input, is unchanged: it never adds a snapshot, so Kogen's builder input is unaffected. Kogen gets a snapshot only if it opts in later, and that opt-in is screened separately at Kogen level (wmapk). No event, event field, capability, task field, CLI command or flag, `SessionConfig` field, option or environment variable is added. No timeout changes. The shell's 45-second bounded wait from L-BOUNDED-SHELL-WAIT (f2e30a4) is already on main and stays as it is. There is no Kogen vendored copy, pin, installation, publication or CHANGELOG change: commit history records changes.

## Decisions
- Snapshot message text, exact. It is the header, then `\n\nlist_files:\n`, then L, then one section per shown file in listing order: `\n\nread_file ` + Go `strconv.Quote(<real path>)` + `:\n` + R. Nothing follows the last section, so there is no trailing newline. (source: request)
- The header is exactly `Workspace at the start of the task: the output of list_files, then read_file of every listed file of up to 4096 bytes (larger or binary files are listed only). Files you change later are not updated here.` It is the header of the screened lane patch. (source: request)
- L is exactly what a `list_files` call with no arguments returns to the model in this session, after the existing 16384-byte tool-text bound (`tools.Cut`). This is Git's quoted form, for example `"caf\303\251 notes.md"`. R is exactly what a `read_file` call with only `path` set to that real path returns to the model, also after `tools.Cut`. An empty file therefore has an empty R. (source: request)
- Real path names come from `git ls-files -z --cached --others --exclude-standard --deduplicate --`, in the same order as the listing. If that command fails, or its entry count differs from the number of listing lines, there is no snapshot. Files are read by these real names, never by the quoted listing lines. This follows research's review note that the listing must be checked against `-z` output. (source: request)
- "Listed paths" means the entries of that listing. At most 64 gets a snapshot; 65 or more gets none. Listed-only paths count toward the 64. (source: request)
- "Shown" means the files that get a section. Their file sizes in bytes, the raw content and not the numbered text, must total at most 32768. At 32769 or more there is no snapshot at all; the snapshot is never truncated. Listed-only files do not count toward this total. (source: request)
- A listed file is shown only when all of these hold: `read_file` would neither refuse it nor fail on it (paths outside the root through a symlink, missing tracked files and folders or submodules are listed only); once in-root symlinks are followed it is a regular file (a symlink to an in-root file is shown with its target's content, exactly as `read_file` returns it); it has at most 4096 bytes; it contains no NUL byte; and it is valid UTF-8. (source: request)
- A FIFO, device or other non-regular listed path is listed only, and building the snapshot must never wait on it. A FIFO with no writer must not block the opening. If the implementation opens files with `O_NONBLOCK` for this, its comment states only what the flag does: an open of a FIFO does not wait for a writer, and the opened file must still be checked as regular. The comment claims nothing more about reads or other file types. This follows research's review note that an `O_NONBLOCK` comment overstated what it does. (source: request)
- No snapshot when `list_files` or `read_file` is not enabled. No snapshot for a root that is not a Git repository or for an empty repository. (source: request)
- Interface: the tools package exports `func (t *Tools) Snapshot() string`. It returns the snapshot text above, or `""` when no snapshot applies. It also exports `const SnapshotHeader` with the header text. `loop.Session` appends the message only when `Snapshot()` is non-empty, and only while its conversation is empty (`Session.next`). (source: request)
- Docs: `README.md` and `docs/contract/loop-v1.md` state the opening snapshot rule: where it applies, its bounds and the fact that resume, later rounds and `loop.Run` are unchanged. The contract also updates the comment of `Session.Round` (`first: opening user message ...`). (source: request)

## Source comparison
- Addressed, required behaviour. Opening round only: acceptance `resume`, plus `secondUserTexts` in every snapshot case. list_files and read_file both enabled: `tools`. Small means at most 64 listed paths (`paths`: 64 versus 65) and at most 32 KiB shown (`bytes`: 32768 versus 32769, with a 5000-byte listed-only file that does not count). One user message after the unchanged task text: `userTexts` and `inputItems`. The header and the exact list_files and read_file outputs: `small` compares the whole message byte for byte. Every snapshot case also has the scripted model call `list_files` and `read_file` and requires the snapshot's listing and sections to equal the tool outputs actually delivered. Larger, binary, invalid-UTF-8 and refused files listed only: `kinds` covers 4097 bytes, a NUL, Latin-1, an outside symlink and a deleted tracked file, plus a FIFO (non-regular, must not block) and a 4096-byte single-line file (shown). A 4096-byte file of empty lines is shown, and its section must equal the cut `read_file` output. An in-root symlink is shown. "Otherwise the opening is byte-identical": every no-snapshot case requires one input item that is exactly the task text, and one request.
- Addressed, constraints. Builds on main with the bounded shell wait: HEAD 02ae244 is f2e30a4 plus a local `.kogen/project.yaml` lineup override. Resume, later rounds and out-of-bounds openings are unchanged. Kogen's native builder input is unaffected because `loop.Run` is untouched. No raised timeouts and no new CLI command or flag; also no task field, `SessionConfig` field or option. Both review notes (`-z` and the `O_NONBLOCK` comment) are Decisions above.
- Superseded, lane-tree details. A local copy of the lane tree (`<checkout>/src-wmap`, on 166ec7f) differs from this contract in four ways. It added a `Tools.CommandWait` option for the shell wait; that is not part of this change, because the 45 s wait is fixed on main and stays an unexported constant. It read files by the quoted listing lines; this change reads them by their `-z` names. It wrote `(empty file)` for an empty file; the request says the exact read_file output, so an empty file has an empty section. It used uncut numbered text; this change uses the delivered, cut text. The reviewed lane diff `wmap.diff` 3613cdad, the kogen-bench fddd22d7 `reproduce/loop-workspace-snapshot-166ec7f-eu/README.md` and `notes-harness/loopclimb/wmap.md` were not available on this machine: the local research checkout is at 7a0e22ad, without that reproduce folder. - Addressed as motivation, not as thresholds. On loop main (loopfx3, 14 kits), 38 of 222 requests (17.1%) were orientation-only before the first edit (l3hard base 52/257). 21 of those 38 were the list-then-read-everything pattern on 11 small kits (14-17 listed files, 3.3-10.8 KB read). Total requests fell 170 -> 122 (-28%). Hidden pass was 25/27 on both arms. Input tokens fell 22% and output 11% where the snapshot fired. One pair was censored (a provider 429 on the unpatched arm), and large repos were unchanged. Add a tools test that compares `Snapshot()` with `Tools.Run` outputs for list_files and read_file on a temporary repository. (unit)
- Larger, NUL, invalid-UTF-8, refused (outside symlink, deleted tracked file) and non-regular (FIFO, without blocking) files are listed only; a 4096-byte file and an in-root symlink are shown; a section equals the cut `read_file` output: acceptance `kinds`. Add the same cases to the tools test, with the FIFO case finishing promptly. (unit)
- Bounds: 64 listed paths get a snapshot and 65 none; shown files totalling 32768 bytes get one and 32769 none, and listed-only files do not count: acceptance `paths` and `bytes`. Add tools tests at the same boundaries. (unit)
- No snapshot without list_files or read_file, or for a root that is not a Git repository or an empty repository; the opening is then the task alone: acceptance `roots` and `tools`. (scenario)
- Opening round only: later requests of the round carry the message once, a resumed round adds none, and a second `Round` on the same Session appends only its feedback. Covered by acceptance `resume` and the `secondUserTexts` observations. Add a loop test of `Session` with a recording provider or Requester on a small temporary repository: the first round's input is the task then the snapshot, and the second round's input adds only the feedback. ## Feasibility
- Repository inspection: the opening input is built in `loop/session.go` `Session.next` (`len(s.input) == 0`). `list_files` is `git ls-files --cached --others --exclude-standard --deduplicate --` with trailing whitespace trimmed (`tools/tools.go` listFiles). `read_file` is `numbered(content)` through root containment (`tools/contain.go`), and the Session cuts every tool text to 16384 bytes. `loop.Run` does not build an opening. No external protocol, provider or library fact is involved, so no documentation lookup was needed.
- Probe (scratch repo, git 2.54.0, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`): list_files prints untracked entries before cached ones. It shows `"caf\303\251 notes.md"` quoted, while `-z` gives the raw name in the same order.
- Scratch control outside the checkout. A `git archive` of HEAD with a reference `Tools.Snapshot` and the `Session.next` change passed the submitted acceptance 7/7. Unchanged HEAD failed all 7, each at its first snapshot assertion (`requests` 1, or `openingUserTexts` without a snapshot). Two wrong variants were rejected. Reading the quoted listing lines failed `small` on the exact snapshot. A blocking FIFO open hung `kinds` until the 30 s CLI watchdog failed it. `go test ./loop ./tools ./api ./cmd/... ./conformance -count=1` passed on the reference implementation.
