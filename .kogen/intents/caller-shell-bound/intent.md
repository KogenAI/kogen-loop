# Add caller-owned shell duration bounds

Slug: caller-shell-bound
Model: .kogen/intents/caller-shell-bound/model.qnt invariants=Truthful,StopWins,Custody seed=17 samples=100 steps=30
Acceptance:

Extend only standalone Loop's Go tool layer with an optional caller-owned duration for each shell call. Zero preserves the existing unbounded behavior, including exact default definitions, ordinary results and replay bytes. A positive bound is a new opt-in capability, not a repair to an unspecified engine regression and not evidence of token savings. No CLI/task/session configuration, Kogen source, adapter, vendored copy, pin or running operation changes.

### Settled technical interface

Add `ShellTimeout time.Duration` to `tools.Tools`, passed separately for every shell invocation to the existing `sys.Options.Timeout`. Follow existing sys semantics: nonpositive is off; positive is the caller's exact duration. Do not add a model argument, environment variable, task field, CLI flag, new default or new capability catalog entry. `loop.Round` already accepts caller-owned Tools and Definitions; use that surface, not a new Round/Session option.

Add `func (t *Tools) Definition(name string) (map[string]any, bool)` for definitions matching that Tools configuration. Existing package functions `tools.Definition`, `tools.Defs` and their bytes stay unchanged. For nonpositive ShellTimeout and all non-shell names, the method returns the same JSON definition/unknown-name behavior as `tools.Definition`. For positive ShellTimeout, change only the shell description's sentence `Commands have no time limit.` to `Each shell call has a caller-configured time limit of <duration>. A timed-out command's process group is stopped before a timed-out result is returned.` Here `<duration>` is Go `time.Duration.String()`. Repeated definition generation at the same duration must serialize identically, without mutating previously returned definitions or shared defaults. Parameters remain command-only, with the existing required list and additionalProperties behavior. Callers explicitly build Round.Definitions from this method and pass the same Tools instance to Round.Tools; Round continues sending caller-supplied definitions verbatim.

Ordinary shell results remain exactly `exit status: <n>\n<combined output>`. Only `sys.Result.TimedOut` produces `timed out after <duration>\nexit status: <n>\n<combined output>`, with nil Go error, ordinary output cutting and ordinary function_call_output/replay pairing. Status is the actual sys exit status, not a fabricated timeout exit code. Partial captured output is retained. A positive bound applies anew to each shell call, not to provider waits, batches or whole rounds.

Inspection found `sys.Run` currently starts asynchronous `Terminate` from a timeout timer but can finish waiting for the leader before teardown completes. Scoped changes in `sys/sys.go` are necessary: when a positive shell timeout actually fires, finish whole owned-group termination and observe disappearance before returning timed-out feedback, including a leader that exits on SIGTERM while its ignoring descendants keep running and descriptors open. Reuse existing session group custody, supervisor, Terminate and its five-second SIGTERM-to-SIGKILL grace; do not introduce a new production wall-clock cap. Stop/join the timeout callback appropriately so completed commands have no late teardown. Inspect races, startup/partial/failure cleanup paths and resource release. Preserve unrelated sys behavior, FinishOnInterrupt and zero-timeout background-command semantics. Keep `sys.Terminate`, `Session.Interrupt` and existing Loop custody/cancellation/`deadline_seconds` behavior unchanged; any additional disappearance wait belongs only to the fired positive-timeout feedback path, not shared termination or cancellation custody. An observed Session interrupt wins over a coincident timeout and remains `*sys.Interrupted`; a cancelled parent Round context remains a stopping context error. Neither may publish a tool result, ending, subsequent call or next fake request after cancellation. Existing hook-error precedence is unchanged.

Cancellation collectors assert leader, child and grandchild disappearance using the existing conformance `pidGone` bounded poll (up to 100 checks separated by 50 ms per PID), rather than an immediate `kill(pid, 0)` snapshot when Run returns. This changes no cancellation expectation besides the observation timing: error kind, empty text, `published:0`, `requests:1`, empty ending, `nextOutputs:[]`, `laterEffect:false`, `returnedInput:false`, `definitionsStable`, `sameGroup` and `goneAtPublish` stay exact. Direct and timeout facts after return and `goneAtPublish` at AfterCall remain immediate, without polling, for both leader modes.

Update `docs/contract/loop-v1.md` (additive Go tool API and opt-in qualification of byte fidelity/process custody) and directly affected public Go comments within the allowed paths. A small README note may describe the library-only option and distinguish whole-round `deadline_seconds`. Do not alter adopted historical unbounded promises in `docs/provenance/`, nor imply Kogen adopted this option. No protocol/schema change is needed.
