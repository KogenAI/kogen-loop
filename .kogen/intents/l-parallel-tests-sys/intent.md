# Parallelize safe sys tools and loop tests

Slug: l-parallel-tests-sys

Make independent Go tests parallel by default in sys, tools and loop after isolating shared resources. Replace avoidable fixed padding with readiness/completion events without weakening existing coverage. Implementation changes are limited to test code and necessary test helpers inside these three packages. Do not change production code or other packages' tests. No new product command, flag or option; no timeout, retry or limit change. No paid provider requests, CHANGELOG entry, install, publish, pin update or runtime switch.

## Decisions
- Preserve protocol, real OS process/signal cleanup, timeout, race and failure-propagation coverage. Keep the real approximately five-second TERM-to-KILL grace in TestInterruptKillsAGroupThatIgnoresSIGTERM, including proof the group survives TERM and eventually dies from escalation. Production cleanup's 20/100 ms polling and the 200 ms lifeline tick are safety mechanisms and remain unchanged. (source: request)
- Keep TestWatchedSignalsMapToExitCodes and its SIGINT/130, SIGTERM/143, SIGHUP/129 cases serial in the parent test process. Go serial tests run before resumed parallel tests. Preserve real signals and assertions that nothing starts afterwards; do not parallelize its signal-sending subtests. Other process-global mutations stay serial unless isolated in a subprocess with private resources. (source: request)
- Add t.Parallel to all independently safe top-level tests and independently safe subtests, not merely enough to satisfy the scheduling smoke gate. Document each remaining serial group beside the tests with its demonstrated shared-resource/order reason; review the complete three-package inventory. Tools tests using t.Setenv, including HOME fixtures, stay serial unless environment-sensitive work moves into isolated test subprocesses. Preserve private temporary directories, sessions, process groups, fixture custody and complete cleanup. Do not introduce a broad lock that merely serializes parallel-marked tests. (source: request)
- Replace sys's 300 ms interrupt-start padding and tools's 200 ms interrupt padding with bounded command readiness, emitted after traps are installed where relevant. Remove sys's post-interrupt 300 ms padding only when teardown/nonexecution is observed equivalently. Helpers must clean up and join spawned work on failure as well as success. Do not introduce unbounded readiness polling or shorten any existing timeout/grace limits. Retain delays that actually test timing, such as a trap intentionally delaying completion. (source: request)
- Do not rename or change the existing test embedding a random TempDir in a subtest name. Compare per-top-level terminal outcome counts including subtest counts instead of unstable fully qualified names, and explicitly report this method. (source: request)
- Delivery requires repeated uncached before/after measurements on the MacBook using Go 1.27.2 with identical source scope/environment, reporting wall, package elapsed, failures and race behavior separately from cache hits and queue wait. Three interleaved before/after ordinary runs plus one before/after race run are required. Require reduced median combined command wall, not an invented absolute target or acceleration in every individual package. Full go test ./... must stay green. (source: request)
