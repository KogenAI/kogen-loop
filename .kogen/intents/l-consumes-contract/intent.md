L-CONSUMES-CONTRACT. Kogen's repositories depend on each other through Go modules, and the owner's rule is two-sided contracts: each repository keeps `contract/` for what it provides and adds one `consumes/<producer>/` suite per Kogen dependency for what it relies on. kogen-loop depends on no other Kogen repository, so it gets no `consumes/` directory. Its side of the rule is that its `contract/` suite must cover everything its consumers use, which they will state in their own `consumes/kogen-loop/` suites.

Today `contract/` (from K-CONTRACTS-LOOP) covers a 226-member inventory taken from six consumers. The consumers have moved on since then. kogen-setup and kogen-review now import kogen-loop too. Seven members that consumers use now have no contract case: `provider.Catalog`, `provider.Info.Models`, `sys.Session.RunContext`, `sys.Session.StartCaptured`, `sys.CapturedCommand.Done`, `sys.CapturedCommand.Snapshot` and `sys.CapturedCommand.Stop`. `contract/` contains none of these names. The consumer lists of 108 table rows have changed. After this change, `contract/` covers the inventory of the eight current consumers, and `contract/README.md` states that kogen-loop consumes no Kogen repository and how that was checked.

What changes:

They pin these consumer-relied behaviours. Each one is a real case: calls with asserted results, not bare references.
   - `provider-catalog` (kogen-setup `setup/init_route.go` picks a route's default model as `Models[0]` of each `provider.Catalog()` entry): `provider.Catalog()` returns, in order, the `Name`s `chatgpt`, `supergrok`, `opencode-go`, `anthropic`, `openai-compatible`. `Models[0]` is `grok-4.7` for supergrok, `kimi-k3` for opencode-go and `claude-opus-5-5` for anthropic. chatgpt and openai-compatible have no `Models`.
   - `sys-run-context` (kogen-verification `verify/probe.go`, `verify/attempt.go`, `verify/env.go`; kogen-shaping `shape/unpassable.go`): `(*sys.Session).RunContext(ctx, command, dir, opts)` of a command that completes returns its `Status` and `Output` with a nil error, as `Run` does, and it honours `Options.Env`. Example: `printf out; exit 3` gives Status 3 and Output `out`. When `ctx` is cancelled while the command runs, it returns the zero `sys.Result{}` and `context.Canceled`: the partial output is discarded, which kogen-verification `verify/concurrent.go` states it relies on. To cancel deterministically after the start, the test cancels only once the command has written a ready file. For example, use `touch <ready>; exec sleep 30`, polled with a bounded deadline. A timer alone could cancel before the command starts.
   - `sys-captured` (kogen-verification `verify/concurrent.go`): `(*sys.Session).StartCaptured(ctx, command, dir)` returns a `*sys.CapturedCommand`. While the command runs, `Snapshot()` returns `sys.Result{Output: <output so far>}`, `false` and a nil error. For example, `printf partial; exec sleep 30` gives Output `partial`, observed by polling `Snapshot` with a bounded deadline of at most 10 seconds. `Done()` is closed when the command ends. After that, `Snapshot()` returns the final result and `true` (`printf done; exit 3` gives Status 3, Output `done`, `true`, nil error). `Stop(cancel)` calls `cancel` and joins the command. When `Stop` returns, `Done()` is closed and `Snapshot()` returns `sys.Result{}`, `true` and `context.Canceled`.
   No test waits on real 45-second shell yields, 5-second termination waits, provider backoff or retry sleeps. The commands above end at once on SIGTERM.

## Decisions
- kogen-loop has no consumes/ directory, because it depends on no other Kogen repository; its contract/ suite must cover everything its consumers use (source: request)
- The suites run in the normal `go test ./...`, with the same isolation as `contract/` (no network, no host paths, no private helpers, deterministic) (source: request)
- State how "every use of a dependency in non-test code is covered" was checked: for kogen-loop, the dependency listing shows none, recorded in `contract/README.md` (source: request)
- No behaviour change, no new command, flag or option; go.mod and go.sum are unchanged (source: request)
