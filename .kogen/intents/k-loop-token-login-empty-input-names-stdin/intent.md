# Name stdin when a key login reads no input

Slug: k-loop-token-login-empty-input-names-stdin
Model: not applicable — one login reads one secret once and either saves it or keeps the saved credential; only the refusal text of one outcome and the terminal test of standard input change, with no new state or transition
Acceptance:
- .kogen/intents/k-loop-token-login-empty-input-names-stdin/acceptance.feature
- features/steps/k-loop-token-login-empty-input-names-stdin__login.js

`kogen provider login anthropic`, `claude-code`, `opencode-go` (and `openai-compatible`) read the secret from standard input through `Client.Login` / `Client.LoginWithBaseURL` in `provider/login.go`, `Input.secret` and `loginKey` / `loginToken` in `provider/keys.go`. A caller that runs them with nothing on standard input (a script, an agent shell, a CI step) today gets a refusal that suggests an interrupt and does not say where the secret comes from:

- `< /dev/null`, and a closed standard input (the Go runtime opens /dev/null on a closed fd 0), are character devices, so `StdinInput()` sets `Terminal`. `stty -g` then fails on a non-terminal, `secret` returns ok false, and the login refuses with `provider/login: Anthropic input interrupted; saved login unchanged`, `provider/login_failed: OpenCode Go input interrupted; saved login unchanged` or `provider/login_failed: Claude Code token input interrupted; saved login unchanged` (exit 4).
- An empty pipe (`printf '' | kogen provider login anthropic`) is non-terminal, reads zero bytes and is refused as `no Anthropic key supplied; saved login unchanged` / `no Claude Code token supplied (the input was empty); saved login unchanged`.

After this change:

1. `StdinInput()` sets `Terminal` only when standard input is a terminal. Decided method: ask the terminal driver with the standard library's `syscall` ioctl on fd 0 (`syscall.TIOCGETA` on darwin, `syscall.TCGETS` on linux, into a `syscall.Termios`) in build-tagged files that follow the `provider/loadavg_darwin.go` / `loadavg_linux.go` / `loadavg_other.go` pattern; other platforms keep today's character-device test. No third-party module is added. `/dev/null`, a closed standard input, pipes and files are therefore non-terminal input; a real terminal (a pseudo terminal included) still gets echo turned off with stty and restored on every path, as today.
2. A secret read that ended with the end of input before any byte was read (zero bytes and EOF, from a non-terminal input or from a terminal) is refused with a text that names standard input and shows that login's piped form without any value. Class, reason and exit code are unchanged, the text keeps `saved login unchanged`, contains neither "interrupted" nor any input, and the saved credential keeps its bytes:
   - `loginKey` (reason `login` for Anthropic, `login_failed` otherwise, exit 4), detail `no <Label> key input was read from standard input; pipe the key: printf '%s' "$KEY" | kogen provider login <name>; saved login unchanged`. Rendered for Anthropic: `provider/login: no Anthropic key input was read from standard input; pipe the key: printf '%s' "$KEY" | kogen provider login anthropic; saved login unchanged`. For OpenCode Go: `provider/login_failed: no OpenCode Go key input was read from standard input; pipe the key: printf '%s' "$KEY" | kogen provider login opencode-go; saved login unchanged`. `openai-compatible` uses the same template with its label `OpenAI-compatible` and name `openai-compatible`, like the existing `run kogen provider login <name>` hints.
   - `loginToken` (reason `login_failed`, exit 4), detail `no Claude Code token input was read from standard input; pipe the token: printf '%s' "$TOKEN" | kogen provider login claude-code; saved login unchanged`, rendered `provider/login_failed: no Claude Code token input was read from standard input; pipe the token: printf '%s' "$TOKEN" | kogen provider login claude-code; saved login unchanged`.
   `$KEY` and `$TOKEN` are literal text in the message, never a value.
3. Unchanged: input that was read but holds no key (a blank line, only whitespace) keeps `no <Label> key supplied; saved login unchanged` and `no Claude Code token supplied (the input was empty); saved login unchanged`. A real interrupt (SIGINT, SIGTERM, SIGHUP through the session) still returns `*sys.Interrupted` (`interrupted by SIGINT`, exit 130). The other ok-false outcomes keep `<Label> input interrupted; saved login unchanged` / `Claude Code token input interrupted; saved login unchanged`: a read error, invalid UTF-8, and a terminal whose echo cannot be turned off. Invalid key and token texts, the 16384-byte bound, the save path, the success lines `<name>: key saved (not verified)` / `claude-code: token saved (not verified)` and every other login are unchanged. The secret is never echoed.

This repository has no `kogen` command; acceptance builds a stand-in `kogen provider login <name>` from the public `provider.Client.Login` with the process's real standard input, HOME and signals (see the step file), so the scenarios exercise `StdinInput()` itself.

## Decisions
- The refusal for zero bytes read names standard input and shows the piped form of that provider's login with no value, in the exact texts above (`pipe the key: printf '%s' "$KEY" | kogen provider login <name>`, `pipe the token: printf '%s' "$TOKEN" | kogen provider login claude-code`) (source: request)
- Class, reason, exit code 4 and "saved login unchanged" stay; the zero-byte refusal does not contain "interrupted" (source: request)
- A real signal interrupt keeps its "interrupted" text (source: request)
- Invalid key or token input keeps its current text, and a valid key in a file given with `< file` still signs in (source: request)
- The secret is never echoed (source: request)
- StdinInput sets Terminal only for a real terminal, detected with the standard library syscall ioctl (TIOCGETA on darwin, TCGETS on linux) in build-tagged files; other platforms keep the character-device test. (decision: D1, round 1) (constraint: No third-party module (golang.org/x/term) is added) (constraint: A real terminal or pseudo terminal still gets echo turned off and restored) (evidence: provider/keys.go; provider/loadavg_darwin.go; provider/loadavg_other.go) (assumption: Decided under external session probes that Kogen did not record: on go1.27.2 darwin/arm64, /dev/null and a closed fd 0 stat as character devices and stty -g exits 1 on them. A stdlib ioctl test reported false for /dev/null and an empty pipe, true under script(1), and compiled for linux/amd64 and linux/arm64. Linux runtime behavior was not executed.) (source: request)
- Any secret read that ends with EOF after zero bytes, terminal or not, is refused with 'no <Label> key input was read from standard input; pipe the key: printf '%s' "$KEY" | kogen provider login <name>; saved login unchanged' (token: 'pipe the token: printf '%s' "$TOKEN" | kogen provider login claude-code'), keeping class, reason and exit 4. (decision: D2, round 1) (constraint: Blank or whitespace-only input keeps 'no <Label> key supplied') (constraint: Read errors, invalid UTF-8 and stty failure keep 'input interrupted') (constraint: Signals keep *sys.Interrupted) (evidence: provider/keys.go; provider/keys_test.go; provider/login.go; provider/creds.go) (assumption: The current refusal texts for /dev/null, <&- and an empty pipe were observed only through an unrecorded external stand-in build on HEAD 3505e60. Kogen's readiness run of the acceptance will observe them independently.) (source: request)
- Acceptance builds a stand-in `kogen provider login <name>` from provider.Client.Login through go -overlay and runs real shell redirections. The SIGINT case runs under script(1), consuming script's initial ^D before the login reads the terminal. (decision: D3, round 1) (evidence: cmd/kogen-loop/main.go; features/steps/l-credential-stdin-size-bound__login.js; sys/sys.go) (assumption: The script(1) behavior was observed only in unrecorded external probes: macOS script rejects fifo/socket stdin; with stdin /dev/null it sends ^D first; SIGINT gave exit 130 'interrupted by SIGINT' 3 of 3 times. The observer controls are declared in Feasibility for Kogen to run. The Linux script path (-qec) is untested.) (source: request)

## Source comparison
- `kogen provider login anthropic|claude-code|opencode-go < /dev/null`: exit 4, names standard input, piped form, "saved login unchanged", no "interrupted" — addressed by rules 1–2; acceptance scenarios 1–3.
- "standard input closed or empty": closed (`<&-`) addressed by scenario 4; empty pipe by scenarios 5–6 (today `no ... supplied`, now the zero-byte text, because no input was read).
- "the other stdin-read routes": `openai-compatible` shares `loginKey` and gets the same template (rule 2); covered by the unit test, not by acceptance (it needs `LoginWithBaseURL`).
- SIGINT while waiting on a terminal keeps "interrupted": scenario 8 runs the login on a pseudo terminal under script(1) and sends SIGINT.
- Invalid key keeps its text: scenarios 9–10. A `< file` with a valid key signs in: scenarios 11–12.
- Example `pipe the key: printf '%s' "$KEY" | kogen provider login anthropic` is preserved verbatim inside the Anthropic text.
- Blank-line input (one byte read) keeping `no Anthropic key supplied` is the boundary of "zero bytes": scenario 7.
- Superseded: the "input interrupted" refusal for /dev/null and closed standard input, and the "no ... supplied" refusal for an empty pipe.

## Tests
- A zero-byte end of input is refused with the new detail (key logins with their reason, token login with login_failed, exit 4, no "interrupted", saved bytes unchanged), for non-terminal input and for terminal input with a scripted stty: add a table test over `secretLogins` (and openai-compatible through `LoginWithBaseURL`) in `provider/keys_test.go` (unit)
- `StdinInput()` treats /dev/null and a closed standard input as non-terminal input and a pseudo terminal as a terminal: acceptance scenarios 1–4 and 8 through the stand-in `kogen` binary (scenario)
- Empty pipes give the zero-byte text: acceptance scenarios 5–6 (scenario)
- A blank or whitespace-only input keeps `no <Label> key supplied`: the existing `TestKeyLoginTrimsStoresPrivatelyAndPreservesBytesOnRejectedInput` and `TestKeyLoginTerminalEchoIsOffWhileTypingAndRestoredOnEveryPath` cases "blank", "only spaces" and the empty terminal line, plus acceptance scenario 7 (existing)
- Read errors, invalid UTF-8 and a terminal that cannot be silenced keep "input interrupted"; signals return `*sys.Interrupted`: the existing `TestKeyLoginInterruptedInputKeepsTheOldKey` and `TestKeyLoginTerminalEchoIsOffWhileTypingAndRestoredOnEveryPath`, plus acceptance scenario 8 (existing)
- Invalid key and token texts and valid saves are unchanged: the existing keys and contract provider tests, plus acceptance scenarios 9–12 (existing)

## Feasibility
- On HEAD 3505e60 (go1.27.2 darwin/arm64) a stand-in built from `Client.Login` printed `provider/login: Anthropic input interrupted; saved login unchanged`, `provider/login_failed: Claude Code token input interrupted; saved login unchanged` and `provider/login_failed: OpenCode Go input interrupted; saved login unchanged` (exit 4) for `< /dev/null`, the same Anthropic text for `<&-`, and `provider/login: no Anthropic key supplied; saved login unchanged` for an empty pipe. A Go probe showed `/dev/null` and a closed fd 0 stat as character devices on which `stty -g` exits 1. A stdlib ioctl probe (`TIOCGETA` darwin, `TCGETS` linux) reported false for /dev/null and an empty pipe and true under script(1), and built for linux/amd64 and linux/arm64. macOS script(1) refuses a fifo or socket stdin (`tcgetattr/ioctl: Operation not supported on socket`) and, with stdin /dev/null, writes one ^D to the pseudo terminal first; the stand-in takes that EOF before signing in. Under script(1), SIGINT 500 ms after the stand-in reported its pid gave exit 130 and `interrupted by SIGINT` (3 of 3 runs). With the step file below in a scratch copy, the good control passed all 12 cases, and the bad control saw today's keys.go, a message-only fix and a terminal-only fix fail exactly their expected cases. These were external session probes that Kogen did not record.
