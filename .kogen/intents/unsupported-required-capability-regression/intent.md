# Pin unsupported required capability refusal

Slug: unsupported-required-capability-regression
Model: not applicable — the test covers one stateless refusal that ends before any session starts
Acceptance:
- .kogen/intents/unsupported-required-capability-regression/acceptance.feature
- features/steps/unsupported-required-capability-regression__steps.js

Add a model-free regression test for the refusal that `kogen-loop run` makes when a task requires a capability that kogen-loop does not provide, here `subagents`. The refusal already exists in `execute`: it checks each name in the task's `requires` against the provided capability map and refuses an unprovided one before the session is created. The only implementation edit needed is additive coverage in `cmd/kogen-loop/main_test.go`; keep `cmd/kogen-loop/main.go` unchanged. The provided capability set and the capability names are out of scope and unchanged.

## Decisions
- The test runs the command's `run` entry with the arguments `run --task -`, feeds one valid task on standard input (supported protocol, an existing temporary root directory, a prompt, role provider `chatgpt`, and `requires` listing `subagents`), uses in-memory stdout and stderr, and decodes stdout as JSON Lines. It sets `HOME` to an empty temporary directory so a wrongly accepted task can never find a stored login or reach a provider. (evidence: cmd/kogen-loop/main.go; cmd/kogen-loop/main_test.go; api/api.go) (source: request)
- A task requiring subagents produces an `error` event of class `loop` and reason `unsupported_capability` whose detail names `subagents`; `run` returns the invalid-task exit code (`api.ExitInvalid`, 2); and no `session.started` event is emitted. The test names the capability by checking the quoted name in the detail, not the full sentence. (evidence: cmd/kogen-loop/main.go; api/api.go; docs/contract/loop-v1.md) (source: request)
- The events are exactly `error` then `session.ended`, so the error event precedes `session.ended` and `session.ended` is the final event; `session.ended` has `status` `failed` and `exit` 2. An omitted terminal event, or a refusal emitted after it, fails the test. (evidence: cmd/kogen-loop/main.go; docs/contract/loop-v1.md) (source: request)
- Acceptance builds the real command with Go 1.27.2 (`go build -o <temporary binary> ./cmd/kogen-loop`) and runs `kogen-loop run --task -` with that task on stdin in an empty temporary directory and HOME, then asserts the process exit and the events. It then runs the whole package tests via `go test -json -count=1 ./cmd/kogen-loop` as written and with one temporary Go overlay of `main.go` per named wrong implementation (accepting the requirement, starting a session before refusing, the failed exit code instead of the invalid-task code, a detail that omits the capability name, no `session.ended`, the refusal emitted after `session.ended`). The original run must pass with at least one test executed; each altered run must fail an executed test, not a build. No test name is required, and the checkout is never edited. (evidence: go.mod; .kogen/project.yaml; cmd/kogen-loop/main.go; cmd/kogen-loop/main_test.go) (source: request)
- Add one run-level Go regression test in cmd/kogen-loop/main_test.go for a task requiring subagents; leave main.go and the capability map unchanged. (decision: D1, round 1) (constraint: No production change; the main.go edits in controls.json are scratch-only counterexamples.) (evidence: cmd/kogen-loop/main.go; cmd/kogen-loop/main_test.go; api/api.go) (assumption: A command run in a scratch copy (built CLI with a subagents task) printed loop/unsupported_capability then session.ended failed exit 2, but that run is not citable evidence.) (source: request)
