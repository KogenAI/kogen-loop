# Add a lower-only client response budget

Slug: l-respbudget
Model: not applicable — duration validation and selection reuse the existing lifecycle without adding state
Acceptance:
- .kogen/intents/l-respbudget/acceptance.feature
- features/steps/l_respbudget.js

Add `provider.Client.ResponseBudget time.Duration` as a Go-library option. Zero keeps the existing 30-minute default, including wire bytes, diagnostics and retry behavior. Nonzero client values must be in the inclusive range 1 second through 30 minutes. Reject other values from Respond before credentials, network traffic or backoff with `*sys.Error`, class `provider`, reason `refused`, exit 4, detail `response budget must be zero or between 1s and 30m0s`. Keep the package constant `provider.ResponseBudget = 30 * time.Minute`.

The effective logical-call budget is the client value (or 30 minutes for zero), further shortened by an existing positive `Request.Budget` when it is smaller. Preserve existing Request.Budget semantics, including subsecond test overrides and clamping values above the package ceiling; the new minimum/refusal applies to the client option, not that existing request field. A request override must never raise the client ceiling or bypass invalid client validation. The absolute budget continues to cover credential waits, refresh, transport, stream reads, retry backoff and retries; bytes or heartbeats do not renew it. Reuse today's expiry path, including `provider/unavailable`, exit 4 and the existing provider label. When Client.ResponseBudget is zero, retain the detail `response wait exceeded 30 minutes` byte-identically, including when Request.Budget shortens the wait. When Client.ResponseBudget is nonzero, the detail is `response wait exceeded ` followed by the actual effective logical-call budget formatted with time.Duration.String(), including any smaller positive Request.Budget; for example `response wait exceeded 10m0s`. Explicit nonzero 30m therefore uses `response wait exceeded 30m0s`. Add no retry and change no retry policy.

Document the option, units, validation, precedence and zero/nonzero expiry diagnostics in docs/contract/loop-v1.md. No CLI flag, task schema, provider protocol change, consumer synchronization, research execution or real-provider testing. Research lever 4 motivates comparing 30 versus 10 minutes using wall time lost to stalled requests and cells ending provider/unavailable; this change supplies the option, not the experiment. The request notes work was provisionally started by main; inspect and preserve compatible existing work.
