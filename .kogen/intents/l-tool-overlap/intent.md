## Technical contract

Use loop.Run and the provider-backed loop.Direct route as the real integration boundary. Preserve Requester.Request and all existing public struct fields. An internal context-scoped delivery bridge shared by engine/provider is an acceptable way to transport completed items without exposing an option or public field; no exported configuration surface is needed. Legacy Requesters that only return completed responses still work: dispatch their complete batches with the same dependency rules. Do not add production mocking abstractions.

A streamed call is eligible only after its name, id, arguments and position are complete and valid for the existing adapter. Never execute argument fragments. Responses has response.output_item.done; Messages has content_block_stop after tool input assembly; Chat Completions lacks per-call completion markers and must wait for its existing finish validation rather than guess that parseable partial JSON is complete. Non-streaming responses dispatch only after validation. Inspect and reuse each existing accumulator's validation and ordering. Completion notifications must be attempt-scoped: a failed attempt cancels and joins its workers and discards its staged results before existing retry policy proceeds. Never publish failed-attempt outputs or allow a stale notification into a later attempt. Do not change retry counts/backoffs. Already executed filesystem side effects are not promised transactional rollback; 'no partial result recorded' concerns conversation/results/transcript, not rollback of writes.

Build dependency edges in original call order, even when streamed completion notifications arrive out of order. A later call must not bypass an earlier call whose effects are not yet known. Read-only native tools can overlap absent a conflicting write. Writes to distinct provably disjoint filesystem targets can overlap; same target writes, read/write overlaps and path aliases must serialize. Resolve lexical aliases and existing filesystem aliases conservatively; uncertain containment/alias/effects mean a barrier, not guessed independence. list_files/search_text/view_image read scopes must account for their actual implementation. Arbitrary shell commands, probe and unknown/custom-effect calls are opaque barriers against all other calls; do not parse shell text to infer safety. Thus a shell after any write waits, and multiple arbitrary shells remain ordered unless independence can actually be established from existing semantics. Independent native reads and disjoint writes must demonstrably overlap; serializing everything does not satisfy the request.

Use response-local staging indexed by original call position. Dispatching is separate from publication: only a validated successful response with all required tools completed can append replay and ordered outputs and start the next request. Keep terminal calls non-executing; they do not drop subsequent calls and the last terminal wins. Preserve Output.Cut, typed outputs and tool error text; stopping errors remain stopping errors. On stream failure, tool stop, cancellation or deadline, cancel and join in-flight work before returning or retrying; round custody still ends its own process groups, including late registrations and background descendants, without touching pre-round groups. Session/transcript must never save partial response/results. No new limits or silent output changes.
