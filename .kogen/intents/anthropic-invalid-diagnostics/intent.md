## Diagnostic design

The following field/category choices are native technical settlement of the request's explicitly open field design, not additional product scope.

Use a flat string-enum map: required `anthropic_invalid`, with only the applicable `error_type`, `stop_reason`, `block_type`, or `delta_type` qualifier. Exact maps are in acceptance. This avoids generic `event_kind: error`, which would change `tools.DeliveryStatus`. Do not add `http_status`, `code`, `type`, or arbitrary received keys to these new maps. Render exactly one additional `provider failure: <JSON>` detail line through the established `withDiagnostics` convention.

Categories are `sse_error`, `non_success_stop`, `changed_stop_reason`, `empty_result`, `unsupported_block`, `unsupported_delta`, `ordering_or_shape`, `event_after_stop`, `frame_json_or_shape`, `tool_input_json`, `invalid_usage_shape`, `invalid_block`, and `duplicate_tool_id`. Use `invalid_block` with the recognized block type for invalid id/name/input, text/thinking/redacted-thinking shape or missing thinking signature; distinguish duplicate valid tool ids separately. Unsupported/mismatched delta families use `unsupported_delta`.

Error-type allowlist is exactly the existing Anthropic `errorTypes`: invalid_request_error, authentication_error, billing_error, permission_error, not_found_error, request_too_large, rate_limit_error, api_error, overloaded_error. Stop allowlist is end_turn, tool_use, max_tokens, refusal, pause_turn, stop_sequence, model_context_window_exceeded. Block allowlist is text, tool_use, thinking, redacted_thinking, server_tool_use. Delta allowlist is text_delta, input_json_delta, thinking_delta, signature_delta, citations_delta. Missing, ill-typed and all other qualifier values become the literal `unknown`; never stringify or retain them. These are diagnostic vocabulary, not new protocol support.

Preserve rejection precedence: unreadable frame precheck before applying frames, first existing apply rejection, then existing result validation. Explain the rejection actually encountered, not a guessed provider root cause. For changed stop reasons report the attempted new allowlisted reason or unknown. Blank end_turn/tool_use uses empty_result with its stop_reason. Context-window refusal remains ahead of result validation as today. Informational unknown events remain ignored exactly as today.
