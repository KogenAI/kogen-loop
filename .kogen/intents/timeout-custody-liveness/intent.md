### Settled implementation contract

Add optional `Context context.Context` to `sys.Options`. Its purpose here is cancellation of the fired positive-timeout custody wait, including joining timeout teardown and waiting for observation. Nil retains existing callers' behavior. It is not a replacement for the caller's overall execution custody: document that the loop still terminates its round's groups. Preserve zero/nonpositive execution and `FinishOnInterrupt` semantics; the added context must not turn existing unbounded calls into a new timeout/cancellation policy.

Add `(*tools.Tools).RunContext(context.Context, string, map[string]any) (tools.Output, error)` and `CallContext(context.Context, tools.Call) (tools.Output, error)`. Existing Run and Call signatures remain as nil-context wrappers. Pass the call context to sys.Options for positive ShellTimeout only; no mutable per-call context stored on Tools. Wire loop.Run's fallback execution and loop.Session.Round's HandleCall to CallContext with their actual ctx. Return stopping errors unchanged. Before returning any timeout outcome, recheck observed Session interrupt, then ctx.Err(). Preserve hook-error precedence and loop.custody itself.

Remove external `/bin/ps` from positive timeout observation. On Darwin use an in-process numeric sysctl KERN_PROC_PGRP query (`CTL_KERN=1`, `KERN_PROC=14`, `KERN_PROC_PGRP=2`, pgid). A size query alone is NOT absence: Darwin reserves slack even for an empty group. Only a successful data query with actual returned byte length zero proves emptiness. Treat ENOMEM/truncated/failed queries as failure, not an empty snapshot. No kinfo_proc layout parsing is needed for this predicate. Include zombies: on the actual darwin/arm64 Go 1.27.2 host an unreaped zombie has kill(pid,0)==nil but getpgid(pid)==ESRCH, while this group query returns nonempty data until reap. Do not use getpgid alone to discard zombies. Stop retaining historical PIDs when complete group enumeration itself supplies membership; a live PID outside the group must not hold custody. This also avoids making PID reuse by an unrelated process a dependency (reuse itself remains static-only evidence).

On Linux enumerate current /proc process stat group membership, including zombies, using standard library only. A genuinely missing per-PID entry during enumeration is disappearance; inability to read/enumerate or parse required facts is observation failure, never absence. On other platforms return the explicit unsupported observation error below after timeout signalling; do not claim verified native support. Keep platform-specific code build-tagged and the module dependency-free. Host proof is Darwin only; cross-build Linux and distinguish cross-build from executed Linux lifecycle proof.

Add `sys.ErrTimeoutObservation` with exact sentinel text `timeout custody observation failed`. On a failed/unavailable in-process observation, return Result{} and a non-nil error matching errors.Is(err, sys.ErrTimeoutObservation), optionally wrapping diagnostic context. Do not set TimedOut, turn this into `error:` tool feedback, retry silently forever, or publish any result. Timeout signals must already have been dispatched, and existing teardown must be joined unless interruption/context stopping takes precedence. This outcome also applies to positive Timeout callers with no Context, including the shared contract used by Kogen a54aa26 cli/verify/probe.go:168; no Kogen edit is authorized. No arbitrary production wall cap, retry budget or new default. Ordinary successful observations can wait for a genuinely still-owned zombie until it is reaped, but cancellation/interrupt must end that wait independently of an observer's completion.

Launch SIGTERM/SIGKILL teardown independently of observation, never after a potentially blocking query. A query must not block the caller's stop selection: use at most one outstanding observation for this wait, select its result against Session interruption and optional context, and do not start an accumulating goroutine per poll. The existing five-second SIGTERM-to-SIGKILL grace and sys.Terminate/Interrupt semantics stay exact. A slow observer cannot postpone either signal. Observation error is not ownership disappearance. Normal timeout feedback still requires successful whole-owned-group absence, including unreaped zombies, before return/AfterCall snapshots.

Inspect the author-reported timer.Stop race while restructuring this lifecycle. Synchronize ordinary completion versus callback ownership so a failed Stop alone is not evidence that timeout teardown actually won. Keep the smallest lifecycle arbitration necessary; a timeout that already won may legitimately own teardown. Do not broaden into scheduler timing guarantees or unrelated command refactors. Add a focused deterministic arbitration regression if this changes the winning condition.

Positive success and feedback stay exact: `timed out after <d>\nexit status: <n>\n...`, actual exit status, partial output, ordinary cutting/replay and next fake request. Parent SIGTERM-ignoring child/grandchild, early leader exit, immediate timeout-return and AfterCall snapshots remain mandatory. Only cancellation PID facts use bounded disappearance polls.

Update README, docs/contract/loop-v1.md and directly affected public Go comments: optional context forwarding, interrupt/context/observation-error precedence, native observation scope, unsupported platform behavior, no-context outcome and distinction from standalone deadline_seconds (already a context deadline in cmd/kogen-loop/main.go). Do not add a SessionConfig timeout or modify cmd.

The focused regression gate requires these real tests, not empty name-only placeholders: `sys.TestTimeoutCustodyBlockedObservation` holds an observation unresolved while independently observing timeout SIGTERM/SIGKILL and cancellation/interrupt return; `sys.TestTimeoutCustodyObservationError` verifies failed and unsupported observations return Result{} with errors.Is ErrTimeoutObservation, no feedback, and stop precedence; `sys.TestTimeoutCustodyMembership` deterministically distinguishes an owned zombie from a PID now outside the group without forcing PID reuse. Exercise lifecycle outcomes rather than asserting private call order, and add no production abstraction solely for mocking. `tools.TestTimeoutCustodyContextCalls` covers both additive methods, nil wrappers and exact unbounded bytes. `loop.TestTimeoutCustodySessionContext` proves the Session HandleCall context reaches execution with a local fake, without adding a public SessionConfig timeout; `loop.TestTimeoutCustodyHookPrecedence` preserves hook errors versus competing stopping errors. The protected public-entry collector separately exercises loop.Run's fallback. Required test names are executable gate inputs, not proof of their assertions; fresh independent review must inspect their meaning.
